2.1.3

성능 분석에 필요한 시공간 복잡도

  • └공간 복잡도, 시간 복잡도

성능 분석에 필요한 시공간 복잡도

  • 성능 분석 : 프로그램 평가 시 정확성 & 효율성을 보는데, 효율성 판단법으로는 성능 분석 & 성능 측정이 있음
  • 공간 복잡도 : 알고리즘의 수행을 끝내기 위해 요구되는 기억 공간의 양 (= 메모리를 얼마나 쓰는가), 고정 부분 + 가변 부분으로 이루어짐
    • 고정 부분 : 알고리즘 수행을 위해 사용되는 입·출력의 수와 크기에 의존하지 않는 기억 공간 요구
      • 명령어 공간, 단순 변수 저장 공간, 상수·구조체 변수 저장 공간 등
    • 가변 부분 : 풀려고 하는 문제의 인스턴스 I에 의존하는 공간
      • 가변 공간, 스택 공간
    • 공간 요구량 : S(P) = C + Sp(I) (C = 고정 부분, Sp(I) = 가변 부분)
  • 시간 복잡도 : 알고리즘을 프로그램으로 작성하여 수행 후, 수행 종료까지 요구되는 시간의 양
    • 명령어 수행에 소요되는 시간 × 명령어 수행 횟수
    • 알고리즘의 표현 언어나 컴퓨터 기종에 따라 차이 날 수 있음
    • 알고리즘의 연산 차수 결정이 중요 (알고리즘을 구성하는 각 연산의 실행 빈도수의 합)
    • 알고리즘 연산 차수가 각각 다르다면 가장 높은 차수 선택
  • 성능 분석 방식
    • 카운터 변수 이용 방식
    • 테이블 방식 : 각 문장의 총 단계수를 나열하는 테이블을 구성하는 것
      • 테이블에 포함되는 것: 문장에 대한 단계수 (steps/execution: s/e), 빈도수 (문장 수행 횟수 / 비실행 문장의 빈도수 = 0), 총 단계수 (s/e × 빈도수)
    • 프로그램 단계 : 실행 시간이 인스턴스 특성에 구문적, 의미적으로 독립성을 갖는 프로그램 세그먼트
      • 단계수 0 : 주석, 선언문, 함수
      • 단계수 1 : 산술식, 지정문, 함수 호출, 메모리 관리 문장, 분기문
      • 단계수 n : 반복문
2.1.4

점근 표기법

점근 표기법

  • 점근적 표기법 : 차수 중 최고차수로 표기
    • 점근적 분석 : 입력 크기가 충분히 클 때에 대해 분석하는 것
    • 점근적 증가율 : 입력의 크기에 따라 증가하는 비율
  • O-표기법 (빅오) : 큰 것 중 제일 작은 것
    • n ≥ n₀ 인 모든 n에 대해서 f(n) ≤ c·g(n)을 만족하는 양의 상수 c와 n₀이 존재한다면 반드시 f(n) = O(g(n))을 만족하고, f(n)은 g(n)의 big oh라고 읽는다
  • Ω-표기법 (오메가) : 작은 것 중 제일 큰 것
    • n ≥ n₀ 인 모든 n에 대해서 f(n) ≥ c·g(n)을 만족하는 두 양의 상수 c와 n₀가 존재하기만 하면 f(n) = Ω(g(n))이다
  • θ-표기법 (세타) : 제일 정밀 (오메가 ~ 빅오 사이)
    • n ≥ n₀ 인 모든 n에 대해서 c₁·g(n) ≤ f(n) ≤ c₂·g(n)을 만족하는 세 양의 상수 c₁, c₂, n₀가 존재하기만 한다면 f(n) = θ(g(n))이다
    • 세타 표기법은 빅오나 오메가보다 정확 – 빅오처럼 터무니없이 큰 함수를 잡거나 오메가처럼 작은 함수를 잡지 않음
  • 증가율 순서 : O(1) < O(log₂n) < O(n) < O(n·log₂n) < O(n²) < O(n³) < O(2ⁿ) < O(n!)
  • 빅오 표기 정리
    • 선형 리스트 : 데이터 탐색 O(1), 삽입·삭제 O(n)
    • 힙 트리 : 삽입 시 삽입 후 재구성, 삭제 후 재구성
      • 높이 = ⌈log₂(n+1)⌉
      • 삽입 함수의 시간복잡도 = O(log₂n), 삭제 함수의 시간복잡도 = O(log₂n)
    • 이진 탐색 트리 : 탐색·삭제 모두 높이가 h인 이진 탐색 트리에서 O(h)
      • 분석 (완전 이진 트리에 가까울수록 성능 우수) : 최선 O(log₂n) – 완전 BT, 최악 O(n) – 사향 BT, 일반적 O(log₂n)
    • AVL 트리 : 분석 = O(log n), 균형 유지에 비용이 많이 듦
    • 레드블랙 트리 : 수행 시간 = O(log₂n)
    • 스플레이 트리 : 연산 상환 시간 = O(log₂n)
    • 최소비용 신장트리 : Kruskal 전체 연산 시간 = O(e·log₂e), Prim 구현 시간 = O(n²)
    • 최단 경로 : Dijkstra = O(n²), Bellman-Ford = O(n³)
    • 탐색 : 순차 탐색 = O(n), 이진 탐색 평균 O(log₂n − 1)·최악 O(log₂n), 해싱 = O(1)
    • 정렬
      • 삽입 정렬 : 평균 O(n²), 최악 O(n²), 최상 O(n)
      • 버블 정렬 : 평균 O(n²), 최악 비교 O(n²), 최악 교환 O(n²), 최상 O(n) – n−1번 비교 (정렬되어 있는 경우)
      • 선택 정렬 : 평균 O(n²), 비교 O(n²), 교환 O(n) 원본과 다름 · 원본: “교환 = O(n²)”, 선택 정렬은 한 바퀴에 한 번만 교환해 교환 횟수가 n−1번
      • 퀵(피봇) 정렬 : 평균 O(n·log₂n) 원본과 다름 · 원본: “평균 O(log₂n)”, 퀵 정렬 평균은 O(n·log₂n), 최악 O(n²), 최상 O(n·log₂n)
      • 기수 정렬 : O(d(n+r))
      • 합병 정렬 : O(n·log₂n)

반복 (iteration)과 순환 (recursion)

  • └순환의 개념, 순환 예시 (거듭제곱, 피보나치수, 하노이타워 등)

반복 (iteration)과 순환 (recursion)

  • 순환 (= 재귀, recursion) : 알고리즘이나 함수가 자기 자신을 호출하여 문제를 해결하는 프로그래밍 기법
    • 직접 순환 : 함수가 수행 완료 전 자기 자신을 다시 호출
    • 간접 순환 : 자기 자신을 호출하는 다른 함수를 호출
    • 꼬리 순환 : return n * factorial(n-1); (반복으로의 변환이 쉬운 편)
    • 머리 순환 : return factorial(n-1) * n; (반복으로의 변환이 어려운 편)
    • 기출문제 스타일 : 박스 넣기 (재귀적 정의) / 결과 찾기 / 추적 & 분석
  • 반복과 순환 : 서로 변환 가능 (각자 적합한 상황이 다름) 원본과 다름 · 원본: “반복(분할정복) vs 순환(동적계획)”, 코드 간결·효율 낮음(스택 사용) 쪽이 순환이라 두 열 이름이 서로 바뀌어 있음

의사 코드
//막대 A에 쌓여 있는 n개의 원판을 막대 B를 사용하여 막대 C로 옮긴다
void hanoi_tower(int n, char A, char B, char C) {
    if (n==1)
        A에 있는 한 개의 원판을 C로 옮긴다.
    else {
        1) A의 맨 밑의 원판을 제외한 나머지 원판들을 B로 옮긴다.
        2) A에 남아 있는 한 개의 원판을 C로 옮긴다.
        3) B의 원판들을 C로 옮긴다.
    }
}
코드
#include <stdio.h>
void hannoi_tower(int n, char A, char B, char C) {
    if (n==1)
        printf("원판에 %d를 %c에서 %c로 옮긴다.\n", n, A, C);
    else {
        hannoi_tower(n-1, A, C, B);
        printf("원판에 %d를 %c에서 %c로 옮긴다.\n", n, A, C);
        hannoi_tower(n-1, B, A, C);
    }
}
int main(void) {
    hannoi_tower(4, 'A', 'B', 'C');
    return 0;
}
  • if (n==1) → 종료 지점 (원판이 한 개면), printf → move (A → C 이동)
  • hannoi_tower(n-1, A, C, B) → A를 C를 이용해서 B로
  • printf → move (제일 큰 애 A에서 C로 이동)
  • hannoi_tower(n-1, B, A, C) → B를 A를 이용해서 C로
